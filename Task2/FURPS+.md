# FURPS+ Таблица требований

| Код   | Категория                        | Требование                                                                 | Комментарий |
|--------|----------------------------------|-----------------------------------------------------------------------------|-------------|
| **F**  | **Функциональные**               |                                                                             |             |
| F1     |                                  | Поддержка подачи заявок на депозиты через сайт и интернет-банк             | MVP: сайт — ФИО и телефон; ИБ — сумма и счёт, подтверждение через СМС |
| F2     |                                  | Поддержка подачи заявок на кредиты через сайт и интернет-банк              | Предварительное решение по скорингу на сайте, предодобренные предложения в ИБ |
| F3     |                                  | Отображение ставок: стандартные и персонализированные                      | Включая поддержку XLS-файлов и АБС для управления |
| F4     |                                  | Интеграция с АБС и кредитным конвейером для обработки заявок               | Сотрудники работают с заявками и принимают решения |
| F5     |                                  | Отправка СМС-уведомлений клиентам                                          | После подачи, изменения статуса, подтверждения |
| F6     |                                  | Документооборот и ведение истории заявок                                   | Для соблюдения нормативных требований и аудита |
| **U**  | **Удобство использования**       |                                                                             |             |
| U1     |                                  | Использование дизайн-системы банка                                         | Привычный интерфейс, фирменный стиль |
| U2     |                                  | Быстрая реакция интерфейса                                                 | Миллисекунды, устранение задержек справочников |
| U3     |                                  | Единая UX-логика на всех каналах (сайт, ИБ)                                | Согласованность пользовательского опыта |
| **R**  | **Надёжность**                   |                                                                             |             |
| R1     |                                  | Доступность интернет-банка 99.9%                                           | Включая переключение на резервный ЦОД |
| R2     |                                  | Устойчивость к сбоям                                                       | Горизонтальное масштабирование фронтов |
| R3     |                                  | АБС не должна быть точкой отказа                                           | Минимизировать прямой доступ к API АБС |
| **P**  | **Производительность**           |                                                                             |             |
| P1     |                                  | Время отклика интерфейса < 1 сек                                           | Для критических операций — < 500 мс |
| P2     |                                  | Поддержка массовых параллельных заявок                                     | Включая пиковые часы |
| P3     |                                  | Эффективное использование БД                                               | Перераспределение нагрузки, кеширование |
| **S**  | **Поддерживаемость**             |                                                                             |             |
| S1     |                                  | Использование текущих технологий: MS SQL, Oracle                           | Минимизация внедрения новых СУБД |
| S2     |                                  | Возможность перехода на микросервисы (в рамках MVP)                        | Особенно для открытия депозитов |
| S3     |                                  | Документация и архитектурные артефакты                                     | Для масштабирования и поддержки |
| S4     |                                  | Платформенная совместимость с существующим стеком                          | Языки программирования, библиотеки |
| **+R** | **Ограничения и архитектура**    |                                                                             |             |
| +R1    |                                  | Данные по ставкам ведутся в XLS — требуется централизовать                 | Вариант: реализовать в АБС с доступом для обоих бэк-офисов |
| +R2    |                                  | Использование Kafka — перспективно, но несовместимо с текущим ИБ           | Возможно использовать при миграции ИБ на микросервисы |
| +R3    |                                  | Прямая интеграция с АБС ограничена из-за её архитектуры                    | Избегать нагрузки на БД АБС, не масштабируется горизонтально |
| +R4    |                                  | Защита чувствительных данных (ФИО, паспорт и пр.)                          | Шифрование трафика при передаче на сайт и в ИБ |
| +R5    |                                  | СМС-функциональность ограничена текущим ядром                              | Предпочтительно реализовать без привлечения подрядчика |
